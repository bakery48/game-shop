# 中古ゲームショップ経営＋架空ソフト収集 — プロトタイプ

仕様書 v0.1 の「10. プロトタイプの範囲」に対応した検証用の実装です。
目的は**資金カーブと図鑑の埋まり方が想定通りかを検証すること**で、面白さの確認は対象外です。
仕様書の方針どおり、これは捨てる前提のコードです。

## 動かす

**ブラウザ版**（見た目は表とボタンのみ）

    index.html をブラウザで開くだけ（ビルド不要・サーバ不要）

配布用に1ファイルへまとめたものが `dist/prototype.html` です。
このファイル単体をブラウザにドラッグするだけで動きます。作り直すには:

    node build/build.js

- 「1ターン自動 / 1週自動 / 最後まで自動」で自動プレイの挙動を確認できます
- 「シミュレーション100回」はブラウザ内で 100 周まわして分布を出します
- seed を変えると同じ条件を再現できます（ソフト150本の内容は seed によらず固定）

**自動シミュレーション**（Node.js）

    node src/sim.js            # 100回
    node src/sim.js 300        # 回数指定
    node src/sim.js 100 --json # 機械可読
    node src/sim.js 100 --balance=rent=20000,startCash=200000   # 定数を上書きして比較

## ファイル

| ファイル | 中身 |
|---|---|
| `src/catalog.js` | 架空ソフト150本の生成（架空ハード4機種・メーカー9社・シリーズ関連付け） |
| `src/engine.js` | ゲーム本体。**バランス定数は先頭の `BALANCE` に集約** |
| `src/policy.js` | 自動プレイの方針。資金カーブ検証の基準線 |
| `src/sim.js` | 100回まわして分布と検証項目を出す |

`src/engine.js` と `src/policy.js` はブラウザと Node の両方から使えます。

## 仕様書の数値について見つかった問題

プロトタイプの主目的はここです。**仕様書 v0.1 の数値のままでは成立しません。**
以下は実装して測った結果わかったことと、暫定的に採った対処です。

### 1. 店番の売上が家賃に対して1桁足りない（最重要）

仕様書の「客3〜4人／ターン」で実装すると、1ターンに売れるのは**最大でも2本前後**です。
50週＝100ターンで170本、平均単価2,518円で**通算42万円**にしかなりません。
家賃だけで50週に150万円かかるので、どう調整しても破産します（初期実装では100%が3週目で閉店）。

仕入れ値・卸値・客数・家賃を総当たりで振っても改善しませんでした。構造的な上限だからです。

**対処**: 客を「判断が要る客（3〜4人）」と「店頭で普通に売れる分」に分けました
（`BALANCE.passiveSales`、既定 7〜12本／ターン）。陳列棚＝売り物という意味づけは変えていないので、
ときメモ風の固定画面・低クリック数を保ったまま売上を成立させられます。

**判断が必要**: 来店数を増やすのか、この分離を採るのか、家賃を下げるのか。

### 2. 開始資金50,000円では2週で詰む

開始資金50,000円＋初期在庫30本（卸価値 約14,000円）に対して家賃は週30,000円で、
運転資金は実質2週分しかありません。まとめ買い1回（30,000〜80,000円）すら打てません。

**対処**: 開始資金を **100,000円** に変更しました。これで閉店率が5%に落ち着きます。

### 3. 棚50枠では150本を同時所持できない（真エンドが定義上不可能）

完全クリア条件は「150本すべてを同時に所持」ですが、初期棚枠は50です。
5節にある棚拡張（最大200枠・10万円）は10節では「作らないもの」に入っていますが、
**これが無いと真エンドに到達できません**。行動フェイズの選択肢として実装しました。

### 4. 激レア15本は「購入」させると破綻する

激レア15本の相場合計は **252万円**（全150本で360万円）です。
オークションで買える設定にすると、資金がすべて吸われて閉店率が45%に跳ね上がります。
8節どおり**イベント報酬**にすれば経済はほぼ閉じます。

**対処**: `BALANCE.ultra.source` で `'event'` / `'auction'` / `'both'` を切り替えられます（既定 `'both'`）。
常連イベントは未実装なので、`'event'` は「12週目以降2週ごとに未所持の激レアが1本手に入る」で代用しています。

なお、4節の「激レアが高額なのは終盤の資金の受け皿にするため」と
8節の「イベント報酬で手に入る」は両立しません。どちらを採るか決める必要があります。

### 5. 強制売却が回復不能な死のスパイラルになる

6節の「家賃が払えない場合は在庫を強制売却」は、一度発動すると
**在庫が減る→売上が落ちる→また払えない**の悪循環に入り、まず戻れません。
測定では、強制売却が0回だったゲームは所持115〜141本、1回でも起きたゲームは所持44本以下という
極端な二極化が出ました。救済措置（分割払い、前借り、猶予週）を検討すべきです。

### 6. 図鑑の埋まりが想定より速い

25週で登録119本（仕様書の想定は80本）。まとめ買い1回で30〜50本入るので登録は一気に進みます。
一方で**所持**は50週かけて120本前後にしか届きません。
仕様書が意図した「登録率90% / 所持率60%」という二層表示は、実測では
**登録93% / 所持80%** に近い形になりました。二層構造そのものは有効に機能しています。

### 7. 「最後の1本を売るか」がゲームの中心にある

自動売上を無条件に許すとコレクションが流出し（1ゲームあたり356回、最後の1本が売れていました）、
逆に全部を守ると売り物が尽きて破産します。
そこで在庫ごとに**「非売品」札**を付けられるようにしました。所持率が下がる売却は必ず判断を通ります。
仕様書に無い要素ですが、無いとゲームが成立しませんでした。

## 仕様書から変更した点（まとめ）

| 項目 | 仕様書 | プロトタイプ | 理由 |
|---|---|---|---|
| 開始資金 | 50,000円 | 100,000円 | 2週で詰むため |
| 店頭売上 | 客3〜4人のみ | ＋自動売上7〜12本／ターン | 売上が1桁足りないため |
| 棚拡張 | 10節では対象外 | 実装（10万円で+50枠、最大200） | 無いと真エンドが不可能 |
| 非売品札 | 記載なし | 実装 | 所持率の維持に必須 |
| 陳列の入れ替え | 「整理」に含む | 無料操作 | 毎ターン1手つぶすと回らない |
| 激レア | イベント限定 | 経路を切替可能（既定は両方） | 経済への影響が大きく要検証 |
| まとめ買い | 30,000〜80,000円 | 中身の相場×0.20〜0.45 | 中身と価格を連動させるため |
