## 動かす

**ブラウザ版**（見た目は表とボタンのみ）

    index.html をブラウザで開くだけ（ビルド不要・サーバ不要）

配布用に1ファイルへまとめたものが `dist/prototype.html` です。
このファイル単体をブラウザにドラッグするだけで動きます。作り直すには:

    node build/build.js        # または npm run build（data/*.json の反映も一緒にやる）

- 「会話を飛ばす」で、判断の要らない客（常連の雑談・受け取るだけのイベント）を自動で進められます。
  何が起きたかは要約カードとログに残り、取引の判断が要る客は飛ばしません。設定はブラウザに保存されます
- 「1ターン自動 / 1週自動 / 最後まで自動」で自動プレイの挙動を確認できます
- 「シミュレーション100回」はブラウザ内で 100 周まわして分布を出します
- seed を変えると同じ条件を再現できます（ソフト200本の内容は seed によらず固定）

**自動シミュレーション**（Node.js）

    node src/sim.js            # 100回
    node src/sim.js 300        # 回数指定
    node src/sim.js 100 --runs=3   # 図鑑を引き継いで3周まわし、周ごとの成績を出す
    node src/sim.js 100 --json # 機械可読
    node src/sim.js 100 --balance=rent=20000,startCash=200000   # 定数を上書きして比較

## テスト

    npm test                # 下の2つをまとめて実行

    node test/check.js      # 依存なし。構文・データ整合性・通し実行・不変条件・配布物
    node test/browser.js    # playwright があるときだけ。ライト/ダーク両方で起動と通し実行

`browser.js` は `npm i -D playwright && npx playwright install chromium` が要ります。
入っていなければスキップされるだけなので、`check.js` は依存なしで常に走ります。

`check.js` が見ているのは主に次の4つです。

- **構文** — `src/*.js` と `build/*.js`。UI全体が構文エラーで死ぬ事故が実際にあったため
- **データ整合性** — 常連イベントが参照するソフト名とスキル名が実在するか、`src/software-data.js` が
  `data/*.json` と一致しているか（`node build/gen-data.js` の実行忘れを検出）
- **不変条件** — 50週を通して、在庫が棚枠を超えない／陳列が陳列枠を超えない／残高が負にならない／
  所持数が登録数を超えない／評判が0〜100に収まる
- **配布物** — `dist/prototype.html` がソースより新しいか、外部参照がGoogle Fonts以外に無いか

意図的にバグを入れて、3種類とも検出できることを確認済みです
（構文エラー・存在しないタイトル参照・棚枠チェックの破壊）。

## 値札売りと指名客

売上の経路は2つあり、**値札売りのほうが安くしか売れません**。

| | 価格 | 本数 | 判断 |
|---|---|---|---|
| 店頭の値札売り | 相場の78〜90% | 6〜18本／ターン（評判・設備で増える） | 不要（勝手に売れる） |
| 指名客 | 相場の95〜125% | 1〜3人／ターン（評判・人手で増える） | 売る／売らない |

**接客できるのは店主ひとりで1ターン3人まで**です。店員を雇うと増えます。
値札売りは設備で、接客は人手で伸ばす、という切り分けにしています。

実測の平均単価は**値札売り5,187円 対 指名客6,755円で、指名客が30%高い**です。

理屈は「棚に並べる＝値札を付ける」ということです。値札は誰が来ても買える値段なので
回転を優先して低めに付けざるを得ず、客は勝手に手に取ってレジに持ってくるだけで
店主が値段を言う場面がありません。一方、指名客は他店を回った末に「〇〇ありますか」と
尋ねに来た客なので、値札に縛られず相場かそれ以上を払います。

安いぶん値札売りは回転が速い（本数が10倍以上）ので、総額では値札売りが大半を占めます。

**値札を下げるだけだと経済が死にます。** 相場の90〜105%から78〜90%へ落としただけで
閉店率が15%→45%に跳ねました（売上の88%が値札売りのため）。
「安く付けるから数が出る」で本数を増やして補償しています。

## まとめ買いと処分品引取の差別化

**ガラクタ（タイトルの無いジャンク品）を廃止しました。** どちらのロットも中身は全部が実在のソフトです。

もともと2つは「大きい版」と「小さい版」でしかなく、軸が規模しかありませんでした。
処分品引取は劣化まとめ買いです。**相手を変えて分けました。**

| | **まとめ買い** | **処分品引取** |
|---|---|---|
| 相手 | **業者・オークション** | **近所の人**（引っ越し、押し入れの整理） |
| 費用 | 相場の20〜45%（上限9万円） | 2,000〜8,000円 |
| 点数 | 16〜26点 | **4〜8点** |
| 中身 | 並品64%・中堅21%・レア13%・激レア1.4% | **並品88%・中堅12%。レア以上は出ない** |
| 状態 | 傷あり45%・並37%・美品18% | **傷あり85%・並15%。美品は出ない** |
| 評判 | 動かない（業者どうしの取引） | **+1.5（町の人に付き合った）** |
| 役割 | **量。回転の主軸** | 少量・安価だが、序盤の評判を作る |

### ガラクタは想像以上に重かった

**廃止するだけで閉店率が27%→14%まで落ちました。** ガラクタは棚枠を占領し、
需要ゼロで売れず、陳列していると評判まで下げる（`junkOnShelf: -0.25`）純粋な死荷重でした。
1ロットに17.4点も入っていたので、その分の棚が実物に置き換わる効果が大きい。

中立に戻すために2つ調整しました。

- **まとめ買いの点数を30〜50→16〜26に**。実タイトルの数（22.1本→20.7本）を揃えるため
- **処分品引取を必ず有料に**（無料50%を廃止）。無料でもらえるのが実物になると強すぎた

区分の比率は**旧 mix の非ガラクタ部分をそのまま正規化**しています。
これで1ロットの平均単価が¥7,035→¥6,838とほぼ変わりません。
並品に寄せる配分（ガラクタの44%を全部並品に回す）だと平均単価が¥4,365まで落ち、
安物だらけのロットになって閉店率52%でした。

**結果**: 閉店率25%（現行27%）、10週目の残高203,851円（現行255,456円）、所持178本。
10週目の残高が下がったのは狙いどおりの方向です。

### 評判を差の軸にした

点数・費用・中身・状態を分けても、処分品引取は**まとめ買いが買えるときには選ぶ理由がありません**。
量でも質でも負ける以上、規模の軸では永久に劣化版のままです。

そこで**引取だけが評判を上げる**ようにしました（`reputation.gain.junkLot: 1.5`）。
業者オークションは誰も見ていないが、近所の人の押し入れを引き取るのは町に付き合うこと、という理屈です。
持ち込み買取で評判が上がる仕組み（`buyFromCustomer: +1.5`）と同じ扱いにそろえてあります。

上がり幅は4段階測って決めました（300回）。

| `junkLot` | 閉店率 | 所持 | 最終残高 |
|---|---:|---:|---:|
| +0（現行） | 30% | 178 | 244,162円 |
| +1.0 | 23% | 178 | 263,382円 |
| **+1.5（採用）** | **22%** | **181** | **241,064円** |
| +2.0 | 21% | 181 | 240,576円 |
| +3.5 | 15% | 185 | 323,891円 |

**評判は終盤に飽和する**ので、効くのは立ち上がりだけです。300回の中央値で:

| | 5週 | 10週 | 最終 |
|---|---:|---:|---:|
| +0 | 20.3 | 33.2 | 96 |
| +1.5 | **23.4** | **37.4** | 96 |

大きく積むほど閉店率は下がりますが、それは差別化ではなく難易度調整です。
**序盤の評判の立ち上がりだけを変え、終盤の到達点は変えない**幅として +1.5 を選びました。
閉店率25%→22%、10週目の残高203,950円→210,100円で、経済への影響はほぼありません。

## 瑠璃 — SNSの導入役

**「SNSで宣伝する」は週では解禁されません。** 瑠璃が初めて来店したときのイベントで開きます。

> 「ねえ、この店ってSNSやんないの？ 今どきフツーやるくない？」　見たことのない客がレジに寄りかかって言った。
> 「いやあ、どうも苦手でね。怖いっていうか」「趣味でやってんじゃないんでしょ。そんなこと言ってる場合じゃないって。ほら貸して」
> スマホを取り上げられ、五分でアカウントができていた。

**この一段が無いと、店主が現代のSNS用語を知っていることに説明が付きません。**
教わっている側として振る舞えば、投稿のログにある「バズる」「数撃つ」が浮きません。

| | |
|---|---|
| 素性 | 20歳。**サトエさんの孫**だが、事情があってしばらく祖母と会っていない |
| 来店の理由 | 「変な店があったから」。用は無い |
| ゲームの知識 | **ゼロ**。箱の形も内蔵電池も初見。来店を重ねるうちに「あれ？ 面白いかも」に傾く |
| 呼び方 | **グッチー**（一方的に付けたあだ名）。誰にでもタメ口 |
| 先代との関係 | **無い**。8人で唯一 |

**タメ口は年齢を隠すのに効きます。** 他の常連は「店長さん」「あんた」「おじさん」と
相手との距離で呼び分けますが、彼女は誰に対しても同じなので、店主の歳の手掛かりになりません。

**先代を知らないのも意図的です。** 他の7人は全員「先代の店」として見ていて、

## SNSで宣伝する

`BALANCE.promo` にあります。**手番を1つ使って投稿する**行動です。効果は2つ。

- **評判が上がる**（1回あたり +0.8。評判側の逓減はそのまま掛かる）
- **持っていないソフトが持ち込まれやすくなる** — 持ち込みの抽選で、
  既に持っているタイトルの重みが下がります（上限まで撒くと 1.00 → 0.15）

**50回で頭打ち**です。それ以降は投稿できますが伸びません（ログの文面も変わります）。
`promoRate` は 0〜1 の線形で、25回なら効きは半分です。

### 効果量の決め方

最初は評判 +2.0 で置きましたが、**強すぎました**。300回で閉店率15%→6%、
10週目の残高が106,793円→144,997円と、せっかく合わせた資金カーブが崩れます。
評判は来客数と値札売りの本数を決めるので、序盤に積むと利回りが良すぎるのです。

| 1回あたりの評判 | 閉店率 | 所持 | 10週目 |
|---|---:|---:|---:|
| 宣伝なし | 15% | 179 | 106,793円 |
| +0.4 | 17% | 172 | 113,488円 |
| **+0.8（採用）** | **17%** | **180** | **103,257円** |
| +1.2 | 9% | 180 | 117,780円 |
| +2.0 | 6% | 180 | 144,997円 |

### 持ち込み効果は「上限まで撒いて図鑑+3本」

評判の効果を切って、上限まで撒いた状態だけを比べました（300回）。

| | 閉店率 | 登録（中央値） | 所持（中央値） |
|---|---:|---:|---:|
| 宣伝0回 | 15% | 182 | 179 |
| **宣伝50回ぶん** | 14% | **185** | **183** |

**手番50個で図鑑3〜4本**です。安くはありません。
効きが小さく見えるのは、**登録が既に182/200まで行っていて伸びしろが18本しかない**ためです。

### 基準線のAIは7回しか撒きません

自動プレイは「評判40未満かつ20週目まで」だけ宣伝に手番を割きます。
評判はすぐ40に届くので、実際には**中央値7回**で止まります。
その状態での成績は閉店率15%→16%、10週目104,105円→104,584円、所持179→180本と**ほぼ中立**です。

基準線は図鑑の進みを目的関数に持っていないので、**持ち込み効果を正しく評価できません**。
50回撒く価値があるかどうかは、人間のプレイヤーが図鑑をどれだけ優先するか次第です。

## 常連イベントは棚が満杯でも消えない

常連イベントは**発生した時点で消費済み**になります。贈り物イベントで棚が満杯だと、
「※棚が満杯で受け取れなかった」とログに出るだけで、**そのイベントは二度と来ませんでした**。

300回まわして数えたところ、**24%の周回で取りこぼしが起きていて、贈り物115件が消滅**、
うち**31件は激レア枠**でした。ログを流し読みしていると気づけません。

対処は二段構えです。

1. **棚が満杯のあいだは、物をくれる／売ってくれるイベントを起こさない**（`gift` / `giftUltra` / `offer`）。
   その常連はふつうの客として来店し、イベントは棚が空くまで持ち越されます
2. それでも渡せなかったときは `fired` を戻して、**次の来店でもう一度出す**。
   買取イベントで資金や枠が足りなかった場合も同じ扱いです（**断ったときは選択なので消費します**）

1だけでは取りこぼしが残ります。来店の列はターンの頭にまとめて作るので、
同じターンの前の客に買い取ったせいで、イベントに回るころには埋まっていることがあるためです。
実測で**24% → 3%**まで落ち、残る3%を2が拾います。

自動プレイの成績は変わりません（激レア所持の中央値17本、常連イベント28/28件で前後とも同じ）。
基準線のAIは激レアをオークションからも拾うので、取りこぼしても最終的には揃うためです。
**人間のプレイヤーにとっては、見えないところで永久に失われるのを止める修正**です。

## 交渉術を4つ足した（入手方法は未定）

`BALANCE.skills` に2つ足しました。**まだ誰も教えてくれません**（`pending: true`、`from: null`）。
`test/check.js` の「スキルを教える常連が実在する」が、未定のものを名前で報告します。

| | 効果 | 内部キー |
|---|---|---|
| **目星** | ロットに良い区分が混ざりやすくなる。並品の一部が上の区分に置き換わる | `lotTier: 0.06` |
| **選り分け** | ロットの中身の状態が一段よくなりやすい | `lotCond: 0.20` |
| **拡散** | 投稿1回が重くなる。評判の伸びも、持ち込みへの効きも上がる | `promo: 0.60` |
| **愛想** | 評判が上がるとき、上がり幅に上乗せされる（下がるときは変わらない） | `repGain: 0.35` |

### 目星 — 形を保ったまま押し上げる

並品から取った分を、**上の区分へその比率のまま**振り分けます。区分どうしの比が変わらないので、
「レアだけ跳ね上がる」ことがありません。**レアが0の配分（処分品引取）は0のまま**です——
比率で配るので、0には何も入りません。これは機械で確認しています。

| まとめ買い（16週目以降） | 並品 | 中堅 | レア | 激レア |
|---|---:|---:|---:|---:|
| 素 | 64.3% | 21.3% | 13.0% | 1.40% |
| 目星あり | 60.4% | 22.6% | 13.8% | 1.48% |

### 選り分け — 一段ずつ上へ送る

各段階の20%を一つ上へ送ります。**上から順に**送るのが要点で、下から動かすと
送った分をもう一度送ってしまいます。

| まとめ買いの状態 | 傷あり | 並 | 美品 | 期待値 |
|---|---:|---:|---:|---:|
| 素 | 45% | 37% | 18% | **1.000** |
| 選り分けあり | 36% | 38% | 26% | **1.054** |

**効くのはロット（まとめ買い・処分品引取）だけ**です。単品入札・持ち込み・イベントは、
そこに在る一本の状態が先に決まっているので触りません。

### 拡散 — 頭打ちの位置は動かさない

`promoRate` は `投稿数 ×(1+拡散) / 50` です。**上限50回という設計は変えず、そこへ早く届く**ようにしました。
投稿1回あたりの評判も同じ倍率で増えます。50回撒いたあとの到達点は素と同じです。

| 拡散 | 20回投稿した時点の効き | 頭打ちに要る投稿数 |
|---|---:|---:|
| なし | 40% | 50回 |
| あり（0.60） | **64%** | **32回** |

### 愛想 — 上げ幅にだけ乗る

`rep()` の**逓減より前**に掛けます。逓減の後に掛けると、評判が高いほど上乗せも小さくなる二重の壁になります。

**下げ幅には乗りません。** 乗せると「愛想がいいほど、断ったときの損が大きい」ことになってしまいます。
`test/check.js` が、上げ幅がちょうど ×1.35 になることと、下げ幅が変わらないことを両方見ています。

### 強さは既存スキルに合わせた

最初 `lotTier: 0.25` / `lotCond: 0.30` で置いたら、**目星だけで最終残高が9倍**になりました。

原因は**まとめ買いの上限価格**です。ロットの値段は中身の相場×0.20〜0.45ですが
**上限9万円**があるので、中身が良くなるほど上限に当たりやすく、同じ9万円でより多くの価値が入ります。
区分を上げる効果が、価格の上限で増幅されていました。

既存スキル単体を物差しにして合わせました（300回、1週目から持たせた場合）。

**顔つなぎだけが取り残されていました。** 原因を切り分けたのが次の節です。

### 宣伝を +0.8 → +2.5 にした — 手番に見合っていなかった

拡散を作ったとき、**倍率をいくら上げても帯に届きませんでした**。
拡散が弱いのではなく、増幅する元の**宣伝という行動そのものが弱かった**からです。

どれくらい弱かったか。`playTurn` を忠実に再現して、**最初のN手番を宣伝に充てる**と（200回）:

| | 閉店率 | 登録 | 所持 | 最終残高 |
|---|---:|---:|---:|---:|
| 宣伝に0手番 | **20%** | 182 | **180** | 172,413円 |
| 宣伝に5手番 | 49% | 153 | **0** | 20,000円 |
| 宣伝に10手番 | 94% | 107 | 0 | 20,000円 |
| 宣伝に20手番 | **100%** | 53 | 0 | 20,000円 |

**序盤の手番を5つ回すだけで閉店率が20%→49%。** 仕入れに使わなかった代償がそのまま死につながります。
余った手番で撒くぶんには無害ですが、それは「受け皿」であって選択ではありません。

置き場所を変えて、「余裕があるときに多く撒く」方針で測り直しました（150回）。

| 評判/回 | 撒かない | 現行の方針（20週/評判40） | 撒き続ける（50週/100） |
|---|---|---|---|
| **+0.8** | 閉店21% 最終**188k** | 閉店19% 最終165k | 閉店17% 最終187k |
| **+2.5** | 閉店21% 最終167k | 閉店14% 最終294k | 閉店13% 最終**394k** |
| +3.5 | 閉店21% 最終177k | 閉店12% 最終253k | 閉店11% 最終271k |
| +5.0 | 閉店21% 最終177k | 閉店9% 最終437k | 閉店9% 最終437k |

**+0.8では「撒くと最終残高が下がる」**（188k→165k）。撒くほど得になる最小の値が **+2.5** でした。
基準線の方針も「撒き続ける」に直しています（`promoUntilWeek: 50` / `promoWhileRepBelow: 100`）——
手番に見合うようになった以上、空いた手番を宣伝に回すのが正しくなったからです。

緩んだぶんは**家賃 32,000円 → 33,000円**で回収しました（閉店率 20%→15%→16%）。

**家賃が調整用のつまみになってきています。** 30,000 → 32,000（常連の抽選を分けたぶん）
→ 33,000（宣伝を強くしたぶん）。ここは一度まとめて見直したほうがよさそうです。

拡散も **0.60 → 1.20** に上げ直しました。宣伝が強くなったので増幅する元ができています
（閉店16%→9%、最終247k→323k）。それでも6つの中では最も弱く、
残高への効きはばらつきます。効いているのは閉店率のほうです。

### 探し物は、どこに付けても赤字だった

切り出した探し物は**単体でも赤字**です。値を下げても符号が変わりません。

| 探し物の強さ | 所持 | 最終残高 |
|---|---:|---:|
| なし | 185 | 315,909円 |
| 0.9 | 176 | 190,530円 |
| 0.6 | 183 | 270,921円 |
| 0.3 | 184 | 291,544円 |
| 0.15 | 185 | 294,642円 |

付け先を単品入札から**持ち込み**に変えても悪化しました（0.9で153,875円）。

**理由は宣伝の第二効果とまったく同じです。所持が素で185/200まで行くので、
未所持へ寄せて得られるものが無く、単価が上がるぶんの損だけが残ります。**
天井に当たっているものを、引き寄せてもしかたない。

`unownedBias: 0.9` のまま**pending として置いてあります**。値を下げても符号が変わらない以上、
調整で解ける問題ではありません。**先に図鑑の伸びしろを作る**（カタログを増やすか、
1周目の所持率を下げる）のが順序で、それができれば探し物と宣伝の第二効果が同時に生きます。

叙述トリックは**細い糸で吊ってあります**。テストで守っていても、
書いている最中に気づけなければ意味がありません。**書く場所に検査を置きました。**

## ボトルネックは在庫であって、需要ではない

「もう一声」（ついで買い 25%→50%）と「棚づくり」を作って測ったら、
**どちらも最初の形では逆効果**でした。原因は同じで、これが今の経済の性格です。

| | 閉店率 | 所持 | 最終残高 |
|---|---:|---:|---:|
| スキルなし | 16% | 185 | 315,909円 |
| もう一声 +0.25 | 13% | 184 | 306,310円 |
| もう一声 +0.50 | 13% | 185 | 299,745円 |
| **棚づくり（陳列枠+5）** | **21%** | 178 | **145,580円** |
| **棚づくり（保管枠+5）** | **12%** | **186** | **463,985円** |

**陳列枠と保管枠で符号が逆になります。**
陳列棚は「値札を付けて相場の78〜90%で早く売る」枠なので、広げると**単価が下がって在庫が痩せます**。
保管庫は「抱えたまま指名客に高く売る／集める」枠なので、広げると効きます。
最初は評判の計算（`shelf.length / 陳列枠`）を疑いましたが、20週の評判は 70.7 対 68.8 で
ほとんど差が無く、原因ではありませんでした。

**「もう一声」も同じ理由で不発です。** 売る力を上げても、減るのは在庫のほう。
測ってはっきりしたのは、**値切り・目利き・目星・選り分け・棚づくりが効いて、
もう一声・拡散・探し物が効かない**——効くのは全部「仕入れる力／抱える力」で、
効かないのは全部「売る力／引き寄せる力」だということです。

**もう一声は0.25のまま pending で残してあります**（測定上は不発）。
需要側のボトルネックを作らないかぎり、この型は成立しません。

## スマホでのレイアウト

**390pxの画面で、ページの幅が920pxありました。** 横に溢れて、ボタンも数字も切れていました。

原因は1行です。

```css
@media (max-width:900px) { .grid { grid-template-columns:1fr; } }
```

広い画面では `minmax(0,1.15fr) minmax(0,1fr)` なのに、**1カラムに畳むときだけ `minmax(0,…)` が外れていました。**
`1fr` は `minmax(auto,1fr)` なので、下限が min-content になります。
表のセルが `white-space:nowrap` なので、その min-content が画面を押し広げていたわけです。

直したのはこの5点。

| | |
|---|---|

## 業者の立替（借金）

`BALANCE.credit` にあります。**上限250,000円・週6%の手数料**で、在庫を減らさずに現金を都合できます。
手番は使いません。週末に手数料が残債に乗り、手元に20,000円を残せる週は自動で返済します。
50週の最後に残っていれば、現金と在庫を叩いて精算します。

### なぜ要ったか — 螺旋の正体を測り直した

「10週目の残高を10万円前後に」は長く未達で、蛇口を絞ると閉店率が跳ねる、で止まっていました。
今回、絞ったときに何が起きているかを測りました（200回、閉店した回と生き残った回を分けて中央値）。

| 週 | 2 | 4 | 6 | 8 | 10 | 12 |
|---|---:|---:|---:|---:|---:|---:|
| 閉店した回 陳列 | 20 | 20 | 20 | 20 | 20 | 20 |
| 生き残った回 陳列 | 20 | 20 | 20 | 20 | 20 | 20 |
| 閉店した回 売上 | 21,600 | 59,300 | 68,800 | 65,800 | 71,300 | 71,800 |
| 生き残った回 売上 | 21,600 | 69,340 | 79,000 | 98,200 | 113,060 | 121,700 |

**陳列は両方とも20枠で埋まっています。** 評判もほぼ同じ（10週で32 対 33）。
差がついているのは**売上だけ**で、つまり**棚に並んでいる物の単価**です。

金が無い → 良いロットに手が届かない → 安物が並ぶ → 売上が落ちる → さらに金が無い。
螺旋の通貨は在庫の**数**ではなく**質**でした。

### 家賃を立て替えても効かない

最初は「家賃が払えないときに立て替える」だけを実装しました。**効きませんでした。**

| 家賃35,000で | 閉店率 | 所持 |
|---|---:|---:|
| 立替なし | 48% | 3 |
| 家賃だけ立替（上限10万） | 50% | 1 |
| 家賃だけ立替（上限30万） | 49% | 1 |
| 家賃だけ立替（**上限無制限・手数料0%**） | **0%** | **49** |

無制限でタダで借りられても所持49本、最終残高は**−759,588円**でした。
借り続けて生き延びるだけで、二度と立ち直りません。
**これは資金繰りの問題ではなく、採算の問題**だという証拠です。
立て替えた金が家賃に消えるかぎり、棚の単価は上がらないので螺旋は切れません。

### 「ロットを買う金」として借りられて初めて効いた

借入先を家賃から仕入れに変えただけで結果が反転しました。

| 家賃35,000で | 閉店率 | 所持 |
|---|---:|---:|
| 立替なし | 48% | 3 |
| 家賃だけ立替 | 50% | 1 |
| **在庫にも使える立替** | **23%** | **179** |

### 床が張れたので蛇口を絞れた

立替を入れたうえで**初期資金を175,000円→100,000円に下げました**。
借入の上限と手数料は、10週目の正味（現金−残債）が10万円前後に来る組み合わせを選んでいます（300回）。

| | 閉店率 | 所持 | 10週目 正味 | 最終残高 | 最大残債 |
|---|---:|---:|---:|---:|---:|
| 従来（立替なし・初期17.5万） | 22% | 182 | 210,100円 | 262,518円 | 0 |
| 上限20万・手数料5% | 18% | 178 | 109,960円 | 243,860円 | 179,060円 |
| **上限25万・手数料6%（採用）** | **17%** | **183** | **102,519円** | 288,010円 | 176,300円 |
| 上限25万・手数料5% | 11% | 182 | 110,493円 | 302,857円 | 179,060円 |
| 上限30万・手数料6% | 11% | 183 | 102,519円 | 298,635円 | 176,300円 |

**仕様書10節の検証項目が初めて4つとも通りました。**

| | 従来 | 現在 |
|---|---|---|
| 10週目の残高が10万円前後 | × 210,100円 | **○ 102,733円** |
| 25週目に図鑑100本 | ○ 151本 | ○ 149本 |
| 200本所持が可能だが余裕はない | ○ 最高197本 | ○ 最高197本 |

閉店率は22%→17%で、緊張感が上がったのに詰みは減っています。

### 最後の精算がないと壊れる

50週目に上限まで借りて買うのが常に得になってしまうので、**終了時に残債を精算します**。
現金で足りなければ在庫を相場の30%で持っていかれます。集めた物が消えるのが罰です。
テスト（`最後まで借りたままなら在庫で精算される`）で、在庫が尽きるまで取られることを確認しています。

## ソフトの状態（最小構成）

`BALANCE.condition` にあります。**傷あり ×0.80 / 並 ×1.00 / 美品 ×1.50** の価格倍率だけを持ちます。

| 決めたこと | 理由 |
|---|---|
| **図鑑には干渉しない** | 登録も所持も「どの状態でも1本は1本」。ここに絡めると真エンドの条件が変わって破綻する |
| **修理・クリーニングの行動を作らない** | 手番がすでに最大のボトルネック。行動を増やさない |
| **在庫で劣化しない** | 時間経過で状態が落ちる仕様は管理地獄になる |

判断が増えるのは2箇所だけです。**持ち込みを買うか**（提示額も状態に連動する）と、
**重複があるとき最良を残すか**。売上の大半を占める値札売りは自動処理なので、
読み込みの負荷はほとんど増えません。

### 仕入れ経路ごとに出やすさが違う

| 経路 | 傷あり | 並 | 美品 |
|---|---:|---:|---:|
| まとめ買い | 45% | 37% | 18% |
| 処分品引取 | 80% | 19% | 1% |
| 客の持ち込み | 30% | 50% | 20% |
| 単品オークション | 10% | 45% | 45% |
| 常連からの譲渡 | 5% | 45% | 50% |
| 開店在庫 | 35% | 50% | 15% |
| 取り寄せ | — | **並で固定** | — |
| **激レア（全経路）** | — | — | **100%** |

取り寄せだけ固定なのは、**料金が状態に連動しないから**です。抽選にすると取り寄せだけが得になります。

### 激レアは美品しか存在しない

**数が少なく、持ち主が大事にしてきたものだけが残っている**という理屈です。
経路をまたいで効かせたいので、状態を決める全経路が同じ関数（`fixCond`）を通ります。

これに合わせて**取り寄せ料金も届く状態に連動**させました。しないと激レアの取り寄せだけが
5割得になります（激レアは相場×1.5×1.6、中堅は相場×1.0×1.6）。

収支への影響は限定的で、**閉店率27%・所持174本は変わらず、残高の中央値だけ
4.3万円→10.2万円**に増えました。激レアの所持数も16→17本。
コレクションが資産になる、という評判システムの狙いと同じ方向です。

**まとめ買いは期待値がちょうど1.0**（0.8×0.45 + 1.0×0.37 + 1.5×0.18）。
状態を入れたこと自体で経済が動かないようにするためで、
`test/check.js` がこの期待値を見ています。わざと傾けるのは数値調整の仕事です。

### 実装中に見つかったこと

**AIの逆選択で閉店率が94%になりました。** 最初に測ったとき経済が崩壊したので原因を追うと、
自動プレイの買取判定が `提示額 ≤ 相場×0.85` という**固定の閾値**でした。
状態を入れると提示額だけが連動するので、**安い傷あり品ばかり買い、美品は一度も買わない**。
単品入札も同じ理由で美品を取り逃がしていました。両方を状態込みの価値で判定するよう直しています。

**分散が原因だと思って倍率の幅を狭めたら、かえって悪化しました**（32%→35%）。
逆選択を直したら27%に戻り、そのうえで幅の広い版（0.7/1.0/1.8）と比べると狭い版のほうが良い、
という順序でした。**先に原因を特定すべきでした。**

もう1件。**新しく仕入れた美品が次のターンまで守られず**、手元の傷あり品に非売品札が
付いたままになっていました。仕入れの直後にも並べ直すよう直しています。

### 収支への影響（各300回、状態あり／なしのA/B）

| | 状態なし | 状態あり |
|---|---:|---:|
| 閉店率 | 24% | **27%** |
| 所持（中央値） | 179 | 174 |
| 最終残高（中央値） | 74,140円 | 43,333円 |
| 最高所持 | 195 | 196 |

**ほぼ中立**で着地しました。残る+3ポイントは複雑さの代償として許容しています。

## 交渉術（金では買えない）

`BALANCE.skills` にあります。**金では買えず、常連との付き合いの中で教わります。**
それぞれ3回目のイベント（7回目の来店）で、商売の話のついでに教えてくれます。

| スキル | 教える人 | 効果 |
|---|---|---|
| 値切り | 大町（同業のライバル店主） | まとめ買いと処分品引取の言い値が25%下がる |
| 目利き | 蜷川（コレクター） | 持ち込みを30%安く買い取り、指名客には25%高く売れる |
| 顔つなぎ | 速水（元ゲーム雑誌ライター） | オークションと取り寄せが30%安くなり、未所持が回ってきやすい |

**周回引き継ぎでは腕として残ります。** 図鑑と交渉術は次の周に持ち越し、資金・在庫・設備は毎周ゼロからです。
「店主の腕は残るが、店の資産は残らない」という切り分けです。

### 客だけでなく業者にも効かせている

測ったところ、**交渉が客との売買だけに効くなら全体の6%**しか動かせませんでした
（±20%で週1,641円。家賃32,000円に対して誤差）。

| 50週の金の流れ | 割合 |
|---|---:|
| 店頭の値札売り（収入） | 59% |
| まとめ買い（支出） | 28% |
| 指名客への販売（収入） | 3% |
| 業者への卸（収入） | 3% |
| 客からの買取（支出） | 2% |
| 単品入札・取り寄せ（支出） | 4% |

値段の交渉という点では業者相手でも同じなので、**仕入れ全体に効かせて範囲を41%まで広げました**。
これで±25〜30%の倍率でも週11,000円規模になり、不自然に倍率を上げずに済みます。

### 引き継ぎで効いてくる

腕が残るので、周を重ねるほど経営が安定します。

| 周 | 所持率（中央値） | 真エンド | 閉店 |
|---:|---:|---:|---:|
| 1周目 | 91%（136本） | 0〜1% | 23% |
| 2周目 | 97%（146本） | 8% | 4% |
| 3周目 | 97%（146本） | 17% | 3% |

## 金で買える設備と人手

`BALANCE.upgrades` にあります。購入には行動フェイズを1回使うので、「買う手番すら惜しい」という判断が生まれます。

| 設備・人手 | 価格 | 上限 | 効果 |
|---|---:|---:|---|
| 倉庫を広げる | 100,000円 | 5回 | 保管枠+50（50→300）。**全200本の同時所持には必須** |
| 陳列棚を増やす | 80,000円 | 4回 | 陳列枠+10（20→60） |
| 店内を改装する | 150,000円 | 3回 | 値札売り+2本／ターン |
| 店員を雇う | 200,000円 | 2回 | 接客+1人／ターン（3→5） |

**設備は棚売りを、人手は接客を伸ばします。** 店員を雇うと指名客に会う機会が増え、
常連と顔を合わせる回数も増えるのでイベントの進みが速くなります。

導入前に測ったところ、**「休む」が行動全体の3%しかなく、手番が真のボトルネック**でした
（まとめ買い53%、整理16%、単品入札12%、取り寄せ11%）。
余剰資金は20週25万→30週45万→40週88万円と推移するので、
10万〜20万円クラスの買い物が受け皿としてちょうど収まります。

自動プレイの実測では1周あたり4.8件購入します（倉庫2.3／陳列棚1.1／改装0.8／店員0.5）。

## 評判システム

**評判 0〜100。開店時は 0（最低）から始まります。** `BALANCE.reputation` にまとまっています。

| 評判が効くもの | 内容 |
|---|---|
| 来客数 | 1〜6人／ターン（評判0で1人、100で6人。週末は少し多い） |
| 常連が来る確率 | 来客枠1回ごとの抽選で15%〜50%（評判0で15%、100で50%） |
| 店頭の賑わい | 自動売上が4〜13本／ターンの範囲で連動 |
| 持ち込みの希少度 | 評判100でレア率が+10ポイント（劇的にはしない） |

上下する要因は「売買のしかた」と「棚の中身」の両方です。

| 上がる | 下がる |
|---|---|
| 持ち込みを買い取る（+1.5） | 持ち込みを断る（−0.6） |
| 指名買いに応じる（+0.5） | 指名買いを断る（−0.8） |
| 値下げ品が売れる（+0.4） | レア以上の最後の1本を手放す（−1.2） |
| 週末に棚が埋まっている（最大+3.0） | 週末に売り物が無い（−2.0） |
| 週末に珍しいものを置いている（1本+0.5、6本ぶんまで） | 陳列中のガラクタ（1本−0.25） |
| | 家賃が払えず在庫を毟られる（−6.0） |
| | 何もしなければ少しずつ忘れられる（毎週−0.5） |

**非売品として抱えているレアも評判に数えます**（半分の重み）。
売らずに持っていることが「あの店には珍しいものがある」という評判になる、という理屈です。

### なぜこの形にしたか

実装前に測ったところ、**コレクションを増やすほど経営が苦しくなる**構造でした。

| 集め方 | 生存率 | 最終残高 | 最終所持 |
|---|---:|---:|---:|
| 集めない | 91% | 807,560円 | 49本 |
| 38週から確保 | 91% | 599,683円 | 133本 |
| 20週から確保 | 77% | 333,034円 | 143本 |
| 12週から確保 | 33% | 69,735円 | 133本 |

ゲームの目標（全本数コンプ）と、生き延びるための最適行動が対立していたわけです。
評判が「珍しいものを置いている店」を評価することで、コレクションが経営資源になり、この対立が解消します。

### 実装中に分かったこと

**評判の初動は鶏と卵になります。** 最初の実装では評判の上下を客との売買だけに紐づけたところ、
客が来ない→評判が上がらない→客が来ない、で10週で全滅しました。
仕入れはプレイヤーが客数と無関係に打てるので、**棚を埋めること自体を評価対象にした**ことで
立ち上げの起点ができました。

**天井は「減衰」ではなく「逓減」で作りました。** 忘れられる速さ（毎週の減点）を強めると
序盤が立ち上がらず生存率だけ落ちて逆効果でした（減点−2.5で生存30%）。
上がるほど上がりにくくする方式（`gainFalloff`）に変えると、序盤を損なわずに天井を遠くできます。
寂れた店が有名になるのは速いが、名店がさらに名を上げるのは難しい、という形です。

**開始資金を100,000円→175,000円に上げました。** 評判0スタートでは来客が1人／ターンしかなく、
売上が家賃に届きません。100,000円だと閉店率62%、175,000円で16%に落ち着きます。

全員が手書きソフトの設定に紐づいています。

### 来客枠の抽選 — 一般客と常連は別々に引く

**一般客の数と、常連が来るかどうかは、独立した抽選です。**

1. 一般客を評判に応じて 1〜3 人（＋週末0.6、±ゆらぎ、店員のぶん）
2. **それとは別に**、常連が来るかどうかを1回だけ引く（評判0で45%、評判100で95%）。**来ても1人まで**

以前は「来客枠1回ごとに一般客か常連かを抽選」していました。
つまり**常連に会うと、その分だけ売買の機会が減っていた**わけです。
常連は基本的に好ましい出来事なのに、会うこと自体がコストになるのはおかしいので分けました。

**例外は漆原だけです。** 冷やかし専門（`alwaysBrowser`）の常連が来た日は、一般客を1人押しのけます。
「来店枠を食うだけの邪魔者」が彼の役割なので、別枠にすると無害になってしまいます。
`test/check.js` が、常連が来た日の客数がちょうど1人多いこと（漆原の日を除く）と、
1ターンに常連が2人以上来ないことを見ています。

### 常連との記憶 — 周回専用の引き継ぎ

**1周目で全員のイベントを見終わる必要はありません。**

ある常連の全4回のイベントを見届けると、**「◯◯との記憶」**が残ります。
記憶のある常連は、**その日の常連抽選が「誰も来ない」だったときに、記憶持ちだけでもう一度引き直されます。**
外れを拾い直すだけなので、1ターンに来る常連が2人になることはありません。

来店率は `1 - (1-c)²` に上がります。評判0なら45% → **70%**、評判100なら95% → **99.75%**。
`test/check.js` が実測値（0.48 → 0.77）が理論値0.70の近くに来ることまで見ています。

**記憶は現金・在庫・評判と違って周回で持ち越されます**（`carryOver.memories`）。
図鑑・交渉術・種明かしと同じ扱いです。1周目で完走できなかった相手も、
2周目は会いやすくなった相手のおかげで手番と来客枠に余裕ができ、順に埋まっていきます。

| | 記憶（中央値） | 下位10% | イベント | 所持 |
|---|---:|---:|---:|---:|
| 1周目 | **5 / 8** | **0** | 28 / 32 | 180 |
| 2周目 | 8 / 8 | 5 | 31 / 32 | 188 |
| 3周目 | 8 / 8 | 7 | 32 / 32 | 182 |

### 記憶は一人ずつ切れる — 絞るほど濃くなる

**引き直しは、記憶を何個持っていても1回きりです。** だから記憶が増えるほど、
1つのパイを分け合って**一人あたりは薄まります**。放っておくと、8つ揃った状態は
「`visitChance` を45%→76%に上げた」のと数学的に同じで、キャラごとの差が消えます。

そこで**常連表から一人ずつオン・オフできる**ようにしました。薄まりが、プレイヤーの選択に変わります。

| 記憶の入れ方 | 常連が来る率 | **黒沢に会えるターン** |
|---|---:|---:|
| 全部切る | 51% | 6.0% |
| **黒沢だけ入れる** | 80% | **30.0%** |
| 黒沢＋1人 | 80% | 17.0% |
| 黒沢＋3人 | 75% | 15.0% |
| 全部入れる（8人） | 76% | 13.0% |

**常連に会える総量は、誰か1人でも入れれば頭打ち**（51%→80%）。
そこから先で動かせるのは**配分だけ**です。「今周は瑠璃のイベントを終わらせる」と決めたら
瑠璃だけ入れる。会いやすさが5倍変わります。

切り方も周回で持ち越します。`test/check.js` が、絞ると濃くなること・
入れる人数を変えても常連の総数が変わらないこと・持っていない記憶は操作できないことを見ています。

**1周目に全員と会いきれないのが正しい形**になりました。
来店のしきい値は 1/4/7/10 のままです。1/3/5/8 まで詰めると1周目で8/8揃ってしまい、
記憶が周回の動機として働きません。

### 分けたぶんを家賃で回収した

常連が枠を食わなくなると、**売買の相手が1周204人→272人に3割増えます**。
そのぶん経済が緩み、閉店率が13%→4%、10週目の残高が113,065円→146,087円になりました。

戻し方を4つ測って、**家賃30,000円→32,000円**を採りました。

| やり方 | 閉店率 | 所持 | 10週目 | 判定 |
|---|---:|---:|---:|---|
| 一般客を 1〜3 → 0.6〜1.9 に減らす | 13% | 179 | 107,428円 | 数字は合うが**接客が187人に減る**。分けた意味が消える |
| 値札売りを 6〜18 → 5〜15 本に減らす | 26% | **26** | 24,263円 | **崖**。立替を入れても採算の問題は救えない |
| 1件あたりの利幅を削る（買0.80〜1.05 / 売1.05〜1.80） | 10% | 179 | 103,065円 | 持ち込みが常に相場超えになり、**買取が成立しなくなる** |
| **家賃 30,000 → 32,000円** | **11%** | **179** | **95,283円** | 採用。接客272人を保ったまま釣り合う（のちに宣伝の強化で33,000円へ） |

**しきい値は 1/4/7/10 のままにしました。** 常連が1ターンに1人までになったので、
100ターンで配れる常連の来店は最大100回しかなく、8人×10回＝80回では1周では届きません。
一度は 1/3/5/8 まで詰めて32/32に戻しましたが、**1周目で全員終わってしまうと
「記憶」が周回の動機にならない**ので、届かないほうを選びました。

序盤は来客が2人を切り、4回に1回は売買が一度も起きません。寂れた店の手触りはここで出しています。

イベントの効果は5種類です。

- **gift** — ソフトを譲ってくれる（激レアの主な入手経路）
- **offer** — 特定のソフトを相場の20〜50%で売ってくれる。買う／断るの判断が発生する
- **info** — まだ存在を知らないソフトが図鑑に載る。**取り寄せで狙えるようになる**のが効く
- **cash** — 客を回してくれる等で現金が入る
- **talk** — 何も起きない。時間だけが過ぎる（漆原専用）

激レア15本のうち8本が常連イベント、残りはオークションから入ります。

### 屋号は姓の暗号

**辻 → crossroads → クロスロード。** 石橋→ブリヂストン、松田→マツダと同じ、
あの世代の実業家の作法です。1938年生まれの男が自分の店に付ける名前として自然で、
**名前を表に出さずにキャリアを終えた男が、唯一自分の名前を残したのが看板だった**、
しかも先人の流儀を借りた暗号だった、という筋になります。

姓が一文字なので「合成語を裏返す」味は無い代わりに、
**辻がクロスロードだと気づく瞬間の落差**で効かせます。意味も乗ります。
66歳で岐路に立った男の店であり、中古屋とは物が通り過ぎていく辻そのものです。

**看板を見ても姓は分かりません。**
プレイヤーは最後まで主人公の家名を知らないまま、図鑑の「辻」を読み続けることになります。

### 主人公は別姓（谷口）

**叔父と同姓にしてはいけません。** 主人公の芯は「生涯なにも署名しなかった男」です。

別姓にすると、**クロスロードは叔父ひとりの署名**になります。
主人公がその看板を下ろさずにいるのは、**自分の名前ではなく叔父の名前を掲げ続けている**ということで、
彼は最後まで何にも名前を出さない男のままでいられます。母方の叔父なので、姓が違うのも自然です。

副次効果が3つあります。

1. **二段の種明かしが別々の鍵を持ちます。** 一段目（辻＝叔父）を解いても二段目には一切近づけません
2. **主人公の伏線が本当に見えなくなります。** 「谷口」は看板とも叔父とも無関係な平凡な姓なので、

   気づく人には早すぎる段階で割れます
3. **推測できるのは「名前」ではなく「事実」になります。** プレイヤーは漆原の詮索や速水の当てこすりから
   「この人、業界にいたのでは」とは思えます。名前は最後に出る領収書で、当てるものではありません

姓「谷口」はどこにも掛かっていません。**平凡さが仕様**です。名簿に並んでいても引っかからないための姓なので、
ここに意味を持たせないこと。

サトエさんも叔父を「先代」としか呼びません。

そのため図鑑の「辻」は、最後まで**主人公と結びつかない宙に浮いた事実**として置かれます。
一段目（登録100%）で叔父＝辻邦彦が確定し、同時に**クロスロード＝辻**が明かされ、
二段目（所持100%）で**名簿のもう一つの姓＝自分**が明かされる、という順序です。

`test/check.js` が「会話に姓が出ていないこと」と

年齢に触れる場面を作らないが、66歳が言わないことも言わせない。
読み返したとき全部の台詞が嘘をついていない状態にします。

そして**たぶん彼女だけが正しく年齢を見抜いています**——72歳は68歳を見間違えません。
ただ、人の歳を口に出したりしないだけです。**唯一だまされていない人が、何も言わない。**

一方的な奉仕にしないため、彼女の取り分も決めてあります。**受け取ってくれる相手が要る。**
息子は帰ってこない。おにぎりを置いていける先が、彼女には必要です。
だから「置いとくわね」と、訊かずに置いていきます。

#### 三人の守備範囲を分ける

「古いゲームに詳しい中年男性」が3人いるので、放っておくと混ざります。持ち札を決めました。

#### 漆原は「後から調べた」世代

漆原を35歳にしたので、彼も1993〜94年を実体験としては語れなくなりました
（スーエレ終了時に7歳）。**体験を後追いに置き換えてあります。**

| 元 | 直した後 |
|---|---|

| 抱き合わせで**買わされた**。子供相手にひどくない？ | **親が押し付けられたらしくて**さ。子供相手にひどくない？ |
| **俺の**は初期型なんだけど、友達んちで聞いた音と違う | うちにあるのは**親の**初期型なんだけど、**動画で**聞いたのと違う |

**むしろ彼らしくなりました。** 異常に詳しいのは生きたからではなく**調べたから**で、
2010年代に自分から1990年代の不便を再現している。90年代を実際に生きたのは
黒沢・速水・蜷川・大町の側で、そこと役割が分かれます。

`test/check.js` は2つの規則で見ています。**ハードが終わったあとに生まれた人**（ゆうた）は
「当時」「子供の頃」「発売日に買った」を一切言えない。**ハード発売時に6歳未満だった人**（漆原・ゆうた）は
「発売日に買った」を言えない。

ゆうたの「おじさん」は年齢を隠す上で効きます。**子供にとっては25歳も70歳も全部「おじさん」**なので、
幅が広いだけでなく、**「おじいさんではない」と錯覚させる方向にも働きます。**
「店長」より積極的なミスリードです。

禁止しているのは**「おじいちゃん」「おじいさん」「お兄さん」「お若い」「若く見える」**で、
どれも年齢を絞ってしまいます。`test/check.js` が機械的に弾いています。

**「若く見える」と言わせるのは禁止です。** 誤導ではなく省略、という原則に反します。
また、常連は**自分の呼び方以外を使わない**ことも見ています
（「」の中は他人の発言なので除外——漆原の母親が「あんた」と言うのは通ります）
- **主人公の姿は出さない。** Godot化で立ち絵を入れるとき、主人公だけは描けない。
  あとから変えると全部描き直しになるので、絵の方針として先に確定させること

  **常連の立ち絵は必要です。** 主人公だけ絵が無いのは一人称視点として何の説明も要りませんが、
  全員に絵が無いと「なぜ誰も描かないのか」が様式の選択として目立ちます。
  常連に立ち絵があるからこそ、主人公の不在が画面構成として自然に見えます。

  ただし2つ条件があります。

  - **主人公が写り込む構図を作らない。** 肩越し、二人が並ぶ画、カウンターを外から見た画は使えない。
    常連は「こちらを向いている単体の絵」に限る
  - **手も描けない。** 68歳の手はシミと皺で一発で年齢が出る。
    カセットを受け取る手を描いた時点で終わる
- `test/check.js` が「主人公の正体をUIに出していない」を機械的に見ています（`src/*` と HTML に
  `谷口誠` が直書きされていないこと）

### 種明かしを二段に分ける

**真エンド到達率は1周目0%・3周目9%です。** そこに全部を置くとほぼ誰も物語を見ません。

| 段階 | 明かすもの |
|---|---|
| 常連イベント（黒沢10回目） | **伏線だけ。**「なあ、あんた。前にどこかで会ったことないか」— 解決しない |

#### 実測の到達率（各100回）

| 周 | 一段目（叔父） | 二段目（主人公） |
|---:|---:|---:|
| 1周目 | **0%** | 0% |
| 2周目 | 14% | 4% |
| 3周目 | 80% | 9% |

**一段目が1周目で0%なのは想定外です。** 設計時に「登録率91〜100%」を
「登録100%への到達率」と取り違えていました。実際には1周目の最終登録数は
中央値182本・最大192本で、**200本ちょうどに届いた回が一度もありません**
（190本以上でも11%）。2周目以降は図鑑を引き継ぐので届きます。

種明かしは動いていますが、**1周目のプレイヤーは何も見られません。**
数値調整の項目に「一段目の到達率」を追加しました。

主人公は最初から全部知っているので、**「気づく」のではなく「黙っていた」**という形にしてあります。
一段目は「――そろそろ、いいだろうか」、二段目は「――もう一つ、言っていなかったことがある」で始まります。
語り口が伏せるのをやめる、という書き方です。

「知る」で他人の正体、「持つ」で自分の正体。ゲームの二層が物語の二層になります。
一段目はプレイヤーに**推測されることを狙って**設計しています。当てて得た自信が二段目を隠します。

**図鑑がそれを記録していないだけ**です。署名しなかった男の経歴が資料に残っていないのは、
むしろそういう男だからで、これは設定と噛み合っています。

種明かしのテキストで「図鑑には出てこないが」と語れる余地を、ここで確保しておきます。

## 世界設定とソフトのデータ

ハードは **SEC（スーパーエレクトリックコンピュータ、通称スーエレ）** の1機種。
カセット式の据置機で、マルチタップ、カセット内蔵の特殊チップ、コンビニでの書き換えサービスに対応していた、
という設定です。

ソフトのマスターデータは `data/software.json` にあります。現在**手書き151本＋自動生成49本**で200本です。
総数を150本から200本に増やしたぶん、生成の仮データが49本復活しています。
`data/software.json` に追記すれば、追記したぶんだけ仮データが自動で押し出されます
（追記後に `node build/gen-data.js && node build/build.js`）。

区分ごとの枠は総数に按分されるので、200本では 並品93 / 中堅40 / レア47 / 激レア20 です。
手書き151本のうち枠に入りきらないぶんは控えに回ります。

### 発売年はハードの寿命の形にしてある

スーエレは**1990〜1998年の1機種のみ**で、それ以前のソフトは1本もありません（後述「ストーリー」参照）。
200本の発売年はこの形です。

```
1990 █████████ 9        1995 ████████████████████████████████ 32
1991 ██████████████ 14   1996 ██████████████████████████████ 30
1992 ███████████████████████ 23   1997 ██████████████████████████ 26
1993 ████████████████████████████ 28   1998 █████████ 9
1994 █████████████████████████████ 29
```

もとは 1990年1本 / 1991年1本 / 1998年1本という平地で、ハードの立ち上がりも末期も無い形でした。
29本の発売年を動かして山にしています。**ジャンルの成立年を見て振り分けました。**

- **1990〜91年へ**: ゴルフ・将棋・麻雀・クイズ・単純なアクション。
  本体と一緒に並ぶ類のもの。格ゲーもぷよ系落ち物もまだ無い時期なので、フォロワー作品は動かせません
- **1997〜98年へ**: 実写取り込み、インタラクティブムービー、特殊カートリッジ、ニッチな経営SLG。
  市場が終わりかけの頃に出る類のもの

生成分49本も一様乱数をやめ、`hardware.yearWeights` で同じカーブに沿うようにしました。

年を触ると壊れやすいので、`test/check.js` が4つ見ています。

- どの年も5本以上あり、中盤が両端より厚い（山になっている）
- **タイトルに入っている年と発売年が一致**（『全日本F1チャンピオンシップ'94』が1996年発売、を防ぐ）
- シリーズ6組の前後関係（IV→V、無印→II など）
- 叔父の年表が1990年から始まり、4つの異なる年に散っている

## 検討して見送った案

同じ案がまた出たときのために、理由ごと残しておきます。

### 電波キャラ（頓珍漢なことを言うが、正体が分かると全部正しかったと分かる常連）

**見送り。** 装置としては良いが、この作品では**機能が既存キャストに分散実装済み**でした。

> 黒沢「あれ、設計した奴を責める気にはなれないな」（設計した本人が目の前にいる）
> 漆原「誰が書いたんだろうね、それ。一本ずつ」（書いた本人に言っている）
> ゆうた「なんでそんなにゲーム詳しいの？ 大人なのに」
> サトエさん「先代にもよく持ってきてたのよ」

**専任キャラを立てると「この人の発言はヒントです」という看板が立ちます。**
分散配置されているトリックを一箇所に集めて広告する形になり、むしろ弱くなる。
普通の人が普通の文脈で言うからプレイヤーは警戒せず、再読時の落差が大きくなります。

書く難度も高く、1本のセリフに4条件（初見で意味不明／正体判明後に正確／
二段目は割らない／30時間後に思い出せる）がかかります。①と④は両立しにくい。

名無しの冷やかし客に1〜2本だけ仕込む案も出ましたが、これも不要としました。

## 決定済みの設計判断

プロトタイプの結果を受けて確定した項目です。

| 論点 | 決定 |
|---|---|
| 店の売上の作り方 | **値札売りと指名客を分離**（下記）。どちらも評判に連動する |
| 激レア15本の入手経路 | **イベント報酬とオークション購入の両方**（`ultra.source: 'both'`） |
| 家賃未払いの処理 | **強制売却のまま**（§6どおり。救済措置は設けない） |
| 全本数コンプの扱い | **到達可能まで経済を強化**（200本では周回前提。3周目で6%） |
| 序盤の緊張感 | **選択肢を段階的に開ける**（棚拡張11週・単品入札16週・取り寄せ26週）＋**評判0スタート**（来客1人／ターンから始まる） |
| 周回引き継ぎ | **図鑑の登録だけ引き継ぐ**（資金・在庫・棚枠は毎周ゼロから）。真エンドは実質「2周目以降の特典」 |

### 8. 「最後の数本を狙い撃つ」手段が存在しなかった

3節は「46〜50週: 最後の数本を狙い撃つ。売らずに買い戻す局面へ」と書いていますが、
仕様書のどこにも**特定のソフトを指名して入手する手段がありません**。
まとめ買いも持ち込みもオークションもすべてランダムなので、
図鑑には載っている（＝一度は手にした）のに二度と戻ってこないソフトが平均20本残り、
所持率は約70%で頭打ちになりました。

**対処**: 「取り寄せ」を追加しました。図鑑に載っているソフトを相場の160%で指名して仕入れられます（1回に最大3本）。
これで所持率の頭打ちが解消し、真エンドが到達可能になりました。
割増料金が終盤の資金の受け皿も兼ねるので、4節の「激レアを資金の受け皿にする」意図も部分的に満たします。

### 9. 序盤の緊張感と全本数コンプは同時に満たせない（評判システム導入前の測定）

「1〜10週は家賃を払うのがやっと」を作るため、序盤の選択肢を絞りました。
棚拡張を11週・単品入札を16週・取り寄せを26週から解禁し、序盤はロットの質も客足も低く抑えています。
結果、**5週目の残高は100,460円**まで下がり、序盤の手触りは仕様書に近づきました。

ただし**10週目は226,010円で、想定の10万円前後には届きません**。
これ以上絞ると、下がるのは残高より先に生存率のほうです。実測すると:

| 序盤の締め付け | 10週目残高 | 崩壊率（所持99本以下） |
|---|---:|---:|
| なし | 333,000円 | 17% |
| 弱 | 283,000円 | 23% |
| 中（採用） | 229,000円 | 33% |
| 強 | 159,000円 | 78% |

10週目の残高を10万円台に落とすには崩壊率が7割を超えます。
原因は5節の強制売却スパイラルで、**「カツカツ」と「詰み」の間に中間状態が無い**ためです。
序盤の緊張感を数値どおりに作りたい場合、避けて通れないのは家賃未払いの救済措置の追加になります。

**→ 解決済み。** 「業者の立替」の節を参照。ここで書いた「救済措置」の見立ては半分だけ当たっていました。
救済措置は要りましたが、**家賃を立て替えても効きません**でした。効いたのは、
立替を**ロットを買う金**として使えるようにしたときです。螺旋の通貨は在庫の数ではなく質でした。
初期資金を175,000円→100,000円に下げて、10週目の正味は102,733円になっています。

### 10. 真エンドは1周目には重すぎる — 周回引き継ぎで解く

200本すべての同時所持は、1周目だと真エンド率が0%です。
これは「チャレンジ要素として、たまにうまくいく」水準としても細すぎます。

**対処**: 周回引き継ぎ（12節の未決定事項）を実装しました。引き継ぐのは
**図鑑の登録と交渉術だけ**です。資金も在庫も棚枠も毎周ゼロから始まるので、経営の難度は変わりません。
ただし登録済みのソフトは最初から取り寄せで指名できるため、完全クリアが現実的な射程に入ります。

| 周 | 開始時の図鑑 | 登録率 | 所持率（中央値） | 最高 | あと一歩 | 真エンド | 閉店 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1周目 | 27本 | 91% | 86%（172本） | 197 | 4% | **0%** | 28% |
| 2周目 | 184本 | 99% | 93%（185本） | 200 | 33% | **2%** | 8% |
| 3周目 | 198本 | 100% | 95%（189本） | 200 | 37% | **9%** | 0% |

3周目でも真エンドは1割に届きません。図鑑が完成していても、
50週目の時点で200本を**同時に**持っているのは別の難しさだからです。

### 引き継げるもの・引き継げないもの

| | 引き継ぐ | 中身 |
|---|:---:|---|
| 図鑑の登録 | **○** | 一度でも手にしたソフトのID。登録済みは最初から取り寄せで指名できる |
| 交渉術 | **○** | 値切り・目利き・顔つなぎ。常連から教わった腕は残る |
| 常連との記憶 | **○** | 全4回のイベントを見届けた相手。次の周でその人に会いやすくなる（周回専用） |
| 資金 | × | `carryOver.cash` を true にすると `cashRatio` 分だけ持ち越せる |
| 棚枠 | × | `carryOver.slots` を true にすると前周の最大枠を引き継ぐ |
| 在庫 | × | 毎周ランダムな30点から |
| 設備・人手 | × | 倉庫も陳列棚も店員も消える。棚枠300→50、陳列40→20 |
| 評判 | × | 99→0。また寂れた店から始まる |
| 常連の来店回数 | × | 白紙に戻り、4件のイベントをもう一度見る |

カタログ200本の中身は毎周まったく同じ（`catalogSeed` 固定）なので、
「あのソフトが存在する」という知識が次周でも使えます。変わるのは客・ロット・オークションの中身だけです。

**交渉術だけは、教わり直しにならないようにしています。** すでに覚えている周回では、
そのイベントが `skillKnown` の別のセリフに差し替わり、報酬が現金になります（2.5万〜3万円）。
1周目に3つとも覚えていれば、2周目以降は合計8.3万円の臨時収入になる勘定です。
測り直したところ2周目の所持中央値は190→185本、真エンドは3周目で6%→9%。
100回ぶんの差なので、ほぼ誤差の範囲です。
知識が揃っても作業ゲーにはならない、という点でこの引き継ぎ設計は機能しています。

## 総数を150本→200本にしたときの調整

最初に「150本より増やせるか」を測った結果が下の表です。本数ごとに最適な立ち回り
（非売品にする時期を本数に応じて遅らせる）をさせています。

| 総数 | まとめ買い回数 | 棚に入れた延べ本数 | 登録実数 | 登録率 | 所持率（中央値） | 真エンド（1周目） |
|---:|---:|---:|---:|---:|---:|---:|
| 100本 | 60回 | 1,120本 | 100 | 100% | 99% | 27% |
| **150本** | 60回 | 1,117本 | 147 | 98% | 95% | 〜1% |
| 200本 | 60回 | 1,082本 | 187 | 94% | 87% | 0% |
| 250本 | 58回 | 1,068本 | 218 | 87% | 63% | 0% |
| 300本 | 54回 | 939本 | 233 | 78% | 5% | 0% |
| 400本 | 33回 | 691本 | 252 | 63% | — | 0% |

総数を増やしても登録実数は伸び続けますが、増え方が総数の1/4以下に落ちます。
原因は3つが重なっています。

**1. 延べ入手数に上限がある（約1,100本）**
行動フェイズは100ターン固定で、まとめ買いに使えるのは最大60回程度。
1ロットで棚に入るのは約18本だけです（残りは枠あふれでその場で業者行き＝図鑑に載らない）。
60回 × 18本 ≈ 1,080本が全体の予算になります。

**2. 同じものを何度も引く（クーポンコレクター）**
1,100回引いても中身は重複だらけです。均等に引けた場合の理論値は
`総数 × (1 − e^(−1100/総数))` で、300本なら287本。

**3. レア帯が構造的に引かれにくい（これが本命）**
実測は理論値より常に低く、しかも差が開きます。ロットの中身の比率が固定だからです。
ロットから出るレアは5.5%固定なのに、カタログではレアが23%（35/150）を占めます。
総数を増やすとレアの本数だけが比例して増えるため、レア1本あたりの遭遇率が反比例して下がります。

| 総数 | 並品 | 中堅 | レア | 激レア |
|---:|---:|---:|---:|---:|
| 150本 | 97% | 100% | 94% | 100% |
| 200本 | 92% | 95% | 78% | 90% |
| 250本 | 85% | 88% | 60% | 68% |
| 300本 | 77% | 77% | **49%** | 53% |

レアが先に破綻します。300本だと半分のレアは存在すら知らないまま50週が終わります。

**副作用: 延べ入手数自体も減る**
総数が増えると在庫の大半が「コレクション＝非売品」になり、売り物の重複が減って収入が落ち、
ロットを買う資金が回らなくなります（400本でまとめ買いが60回→33回に減少）。
本数を増やすと経営そのものが痩せる、という二次効果です。

### 200本にするために入れた変更

上の分析どおりに3点だけ手を入れました。数値そのものの詰めはこれからです。

| 変更 | 前 | 後 | 効く場所 |
|---|---|---|---|
| `catalogSize` | 150 | **200** | カタログ総数。区分は按分（並品93/中堅40/レア47/激レア20） |
| 倉庫の上限 | 3回・保管枠200 | **5回・保管枠300** | 200本を同時に置ける枠がそもそも無かった |
| `bulk.mix` のレア／激レア | 5.5% / 0.55% | **7.3% / 0.8%** | 総数に連動。1本あたりの遭遇率が下がるのを打ち消す |
| `order.batch` | 1本 | **3本** | 取り寄せ1回で最大3本。**これが本命** |

**手番がボトルネックだった、というのが結論です。**
200本にした直後の2周目を見ると、図鑑198/200・所持171/200・在庫246/300枠（54枠空き）・
残高46万円で、取り寄せは100ターン中わずか14回でした。
金も枠も余っていて、足りないのは「1ターンに1本しか指名できない」ことだけです。
取り寄せをまとめ買いにしたところ、2周目の所持中央値が171本→190本に上がりました。

### まだ残っている歪み

- 1周目の閉店率が28%（150本のときは23%）。総数が増えたぶん在庫が売り物に回らない
- 10週目の残高が23万円で、目標の10万円前後を大きく超えている（従来からの課題9と同じ）
- 真エンドは3周目でも6%。周回の到達点としてはまだ細い
